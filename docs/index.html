02快速开始

三步接入:引依赖、告诉框架用户从哪来、在接口上贴注解。权限数据默认内存实现,接入数据库只需实现一个接口。

① 实现 UserProvider,告诉框架用户从哪来

@Bean
public UserProvider userProvider() {
    return new UserProvider() {
        @Override
        public UserInfo authenticate(String username, String password) {
            // 校验凭证(推荐 BCrypt:passwordEncoder.matches(raw, encoded))
            return valid ? new UserInfo("1", "alice", "d2",
                    Set.of("user"), Map.of()) : null;
        }
    };
}

② 配置 application.yml

xuya:
  token:
    header-name: Authorization
    token-prefix: "Bearer "
    timeout-millis: 1800000        # 空闲 30 分钟
    max-sessions-per-user: 2       # 超限顶替登录,踢最旧会话
    permission-cache-ttl-millis: 60000
    exclude-paths: [/login, /error]

③ 在接口上贴注解

@RequiresLogin
@GetMapping("/me")
public Map<String, Object> me() {
    return Map.of("user", LoginContext.getUser().getUsername());
}

@RequiresPermissions("profile:delete")
@DeleteMapping("/profiles/{id}")
public ... // 无权限自动返回 403 JSON:{code:403, message:...}
登录调用 authenticator.login(username, password) 即获得 token;之后请求携带 Authorization: Bearer {token},拦截器自动解析并绑定 LoginContext。

03鉴权注解

四个注解覆盖"能不能进"与"能看多少",支持方法级与类级,AOP 切面统一执行,失败自动映射 401 / 403。

注解语义示例
@RequiresLogin要求已登录,否则 401@RequiresLogin
@RequiresRoles角色校验,ALL(默认)/ANY@RequiresRoles(value={"admin"}, logical=ANY)
@RequiresPermissions权限校验,ANY(默认)/ALL,支持通配@RequiresPermissions("user:delete")
@RequiresDataScope数据权限下限,通过后绑定上下文@RequiresDataScope(DataScopeType.DEPT)

权限表达式为 资源:操作 形式,* 通配:user:* 覆盖 user 资源全部操作,*:* 为超级权限。

04会话模式

同一套 SessionManager SPI,三种实现按需切换:单体应用零配置,集群引入 Redis 即共享,水平扩展选 JWT。

内存会话 默认

starter 内置,空闲超时自动过期,支持并发会话限制与踢人。

  • 零配置开箱即用
  • 空闲续期 / 顶替登录
  • user-types 按体系覆盖策略
  • 跨节点共享
Redis 会话 redis

引入依赖即自动装配,多节点共享登录态,TTL 承载空闲超时。

  • 分布式部署共享会话
  • 踢人 / 在线列表跨节点
  • enabled=false 可关闭
JWT 会话 jwt

配置 xuya.token.jwt.secret(≥32 字节)即启用,验签即校验。

  • 无状态,任意节点校验
  • 绝对过期(写入 exp)
  • 服务端注销 / 踢人
注意:Redis 与 JWT 同时引入时请只启用其一,或直接自定义 SessionManager Bean 覆盖默认装配。

05多体系(端)

体系是开放字符串标识,数量不限 —— "B"、"C" 只是预置的两个常用值, 开放平台 "OPEN"、小程序 "MINI"、IoT 等任意自定义体系直接可用,无需改动框架。 同一应用可同时承载管理后台与消费者端,五层维度全部隔离。

隔离层机制说明
登录体系维度登录 + 用户分表authenticator.login("C", phone, code),UserProvider 按体系分别校验
会话token 前缀标识体系形如 B-xxx / C-xxx / OPEN-xxx,索引与并发限制按体系独立
策略按体系覆盖全局配置C 端 30 天免登录、B 端 30 分钟,互不影响
角色体系专属角色优先于共用角色同名 "member" 在 B/C 端可拥有不同权限
路径Ant 模式路径体系拦截token 体系与路径归属不符直接 403,即使拥有足够角色

C 端登录与账号分表

// C 端登录:手机号 + 短信验证码,签发 C- 前缀 token
authenticator.login(UserType.C, phone, smsCode);

@Bean
public UserProvider userProvider() {
    return new UserProvider() {
        @Override
        public UserInfo authenticate(String userType, String username, String password) {
            return "C".equalsIgnoreCase(userType)
                    ? cUserMapper.verifyPhone(username, password)   // C 端用户表
                    : bUserMapper.verifyAccount(username, password); // B 端用户表
        }
    };
}

体系专属角色(共用角色照常工作)

// "member" 仅 C 体系可见,优先于同名共用角色;B 端同名角色互不干扰
permissionLoader.addRole(UserType.C,
        Role.builder("member").permission("shop:discount").build());

按体系覆盖策略 + 路径体系隔离

xuya:
  token:
    user-types:                 # 按体系覆盖,未覆盖沿用全局
      c:
        timeout-millis: 2592000000      # C 端 30 天
        max-sessions-per-user: 5
      open:
        timeout-millis: 3600000         # 开放平台 1 小时
    user-type-paths:            # 路径体系归属,Ant 模式
      b: [/admin/**, /profiles/**]
      c: [/c/**]
      open: [/open/api/**]
踢人下线按体系粒度控制:invalidateByUserId("C", userId) 仅踢 C 端, invalidateByUserId(userId) 跨全部体系;在线列表 listActiveTokens 返回用户在各体系的全部有效 token。

06数据权限

功能权限管"接口能不能调",数据权限管"数据能看几行"。角色配置级别,用户取全部角色(含继承)中最宽者。

窄SELF仅本人数据
DEPT本部门数据
DEPT_AND_CHILD本部门及子部门
宽ALL全部数据

角色配置级别

Role.builder("manager").name("经理")
    .permission("report:*")
    .dataScope(DataScopeType.DEPT_AND_CHILD)
    .build();

接口声明下限,业务读取可见范围

@RequiresDataScope(DataScopeType.DEPT)  // 级别不足 → 403
@GetMapping("/orders")
public ... {
    DataScope scope = DataScopeContext.get();
    scope.getVisibleDeptIds();  // DEPT={本部门} / DEPT_AND_CHILD={本部门+子部门} / ALL、SELF 为空集
    // 据此拼接 WHERE dept_id IN (...)
}
DEPT_AND_CHILD 需要提供 DeptProvider Bean 返回部门后代;未提供时自动退化为本部门,不阻断启动。

07角色继承

子角色自动拥有父角色的身份、权限与数据权限,支持多级继承;环形配置自动防护,指向不存在的父角色会被安全忽略。

// admin → manager → user:admin 同时拥有 manager 与 user 的一切
Role.builder("manager")
    .permission("report:*")
    .parent("user")          // 继承 user 角色
    .build();

继承展开由 RoleExpander 统一执行(BFS + 防环 + 20 跳上限),权限校验与数据权限解析共用,缓存装饰器同样兼容。

08扩展 SPI

框架只定义契约,数据从哪来由你决定。所有默认实现均带 @ConditionalOnMissingBean,自定义 Bean 直接覆盖。

接口职责默认实现
UserProvider用户来源与登录校验拒绝所有登录(必须自行实现)
PermissionLoader角色 / 权限数据来源InMemoryPermissionLoader
CachedPermissionLoaderTTL 缓存装饰器(防穿透)按配置自动包装
SessionManager会话存储 / 顶替 / 踢人InMemory · Redis · JWT
DeptProvider部门层级(DEPT_AND_CHILD)无,缺失时退化本部门
PasswordEncoder密码加密与校验BCryptPasswordEncoder
DataScopeResolver数据权限解析DefaultDataScopeResolver
